# 0. PURPOSE
# 0. 문서 목적

이 문서는 리본소프트가 홈페이지에서 **무엇을 할 수 있는 회사로 보여야 하는가**를 구조화한다.

This document defines **what Rebornsoft should be understood as capable of doing** on the corporate website.

중요한 점은 과거 제품명을 사업영역으로 나열하지 않는 것이다.

The capability system must not become a catalog of legacy product names.

예를 들어:

- Reborn Face
- AI Reborn Vision
- WeWorld
- 7 Cubic
- Digital Twin
- VR
- Theme Park

를 각각 독립 사업부처럼 보여주지 않는다.

대신 실제 회사 이력에서 반복적으로 확인되는 **재사용 가능한 능력**을 상위 Capability로 재구성한다.

# 1. CAPABILITY DESIGN PRINCIPLE
# 1. 역량 설계 원칙

Capability는 다음 조건을 동시에 충족해야 한다.

## 1.1 Evidence-based / 증거 기반
실제 개발·인증·출시·구축·계약 이력으로 설명할 수 있어야 한다.

## 1.2 Current / 현재성
과거 제품명에 묶이지 않고 현재 프로젝트에도 적용 가능한 표현이어야 한다.

## 1.3 Scalable / 확장성
향후 Theme Park 외의 다른 공간·서비스 프로젝트에도 사용할 수 있어야 한다.

## 1.4 Understandable / 이해 가능성
해외 파트너가 전문용어 설명 없이도 대략적인 의미를 이해할 수 있어야 한다.

## 1.5 Non-hyped / 과장 금지
현재 Evidence보다 큰 전문성을 암시해서는 안 된다.

# 2. RECOMMENDED CAPABILITY ARCHITECTURE
# 2. 권장 역량 구조

리본소프트의 Capability는 **3개의 Core Capability + 1개의 Cross-Capability** 구조로 설계한다.

Rebornsoft should be presented through **three core capability domains plus one cross-capability layer**.

## CORE 01
### Intelligent Interaction
### 지능형 인터랙션

## CORE 02
### Digital Environments
### 디지털 환경

## CORE 03
### Experience Systems
### 경험 시스템

## CROSS 04
### Technology Integration
### 기술 통합

이 구조는 네 개의 독립 사업부를 의미하지 않는다.

The four labels do **not** represent separate business divisions.

`Technology Integration`은 다른 세 Capability를 프로젝트 목적에 맞게 연결하는 **횡단 역량**이다.

---

# 3. WHY 3 + 1
# 3. 왜 3+1 구조인가

네 개를 동일한 카드로 제시하면 일반적인 IT기업의 사업영역 소개처럼 보일 위험이 있다.

A flat four-card structure risks looking like a generic IT services catalog.

리본소프트의 실제 회사사는 다음처럼 더 자연스럽다.

> **사람을 이해하는 기술**
>
> → **사용자가 활동하는 디지털 환경**
>
> → **기술이 실제 공간 경험으로 확장**
>
> 그리고 이 모든 것을 **프로젝트 단위로 통합**

즉:

**Intelligent Interaction**  
→ **Digital Environments**  
→ **Experience Systems**

를 하나의 발전·적용 구조로 보여주고,

**Technology Integration**

은 그 전체를 연결하는 방식으로 시각화하는 것이 적절하다.

This is the capability area most closely aligned with Rebornsoft's current direction.

다만 과거 AI처럼 인증·특허 중심의 객관적 Evidence가 풍부한 영역은 아니므로, 홈페이지에서는 실제 상태를 명확하게 유지한다.

- Installed
- Contracted

---

## Why "Experience Systems" / 왜 Experience Systems인가

### 선택 이유

`Immersive Experience`  
→ 현재 Evidence보다 전문성을 크게 주장할 위험.

`Spatial Experience Design`  
→ 전문 공간·경험 디자인 회사라는 의미가 강해 현재 단계에서 다소 공격적.

`Theme Park Technology`  
→ 회사 전체 방향을 지나치게 Theme Park로 좁힘.

`Experience Systems`  
→ 기술·소프트웨어·미디어·시뮬레이터·콘텐츠가 **하나의 경험을 작동시키는 시스템**으로 연결된다는 의미를 가장 안전하게 전달.

---

## Website Role / 홈페이지 역할

- 현재 회사 방향을 가장 강하게 보여주는 Core Capability
- Physical / Interactive Experience Visual의 중심
- Theme Park 관련 Current Direction과 연결
- 실제 프로젝트 이미지가 충분할 경우 가장 시각적으로 강한 영역

# 15. TERMINOLOGY RULES
# 15. 용어 사용 규칙

## AI
프로젝트·기술 설명에서 사용한다.  
회사 최상위 Category로 사용하지 않는다.

## Computer Vision
Intelligent Interaction 내부의 Technical Term.

## Metaverse
과거 서비스명·프로젝트 역사에서만 사실대로 사용.  
현재 Capability label로 사용하지 않는다.

## Digital Twin
현재도 유효한 기술용어이므로 Digital Environments 아래에서 사용.

## Immersive
실제 Experience가 충분히 몰입형인 프로젝트에 제한적으로 사용.  
회사 전체를 `Immersive Company`로 정의하지 않는다.

## Spatial
향후 공간 경험 프로젝트가 더 축적되면 확대 사용 가능.  
현재 v1.0에서는 보조 용어.

## Experience Design
특정 프로젝트에서 실제 디자인 역할이 확인될 때만 사용.  
현재 회사 전체 Capability명으로는 사용하지 않는다.

## Systems Integration
Spectrascape의 핵심 언어와도 겹치며 현재 회사의 공식 전문영역으로 단정하기 어려우므로 사용하지 않는다.

대신:
**Technology Integration**

을 사용한다.

### Korean Tone

차세대 메타버스 플랫폼을 제공합니다.

### Korean Tone

### Avoid
최고 수준의 몰입형 테마파크 경험을 제공합니다.

### Avoid

# 21. LOCKED CAPABILITY DECISIONS
# 21. Capability 고정안

## LOCK CAP-01
Core Capability는 **3개**로 한다.

1. **Intelligent Interaction / 지능형 인터랙션**
2. **Digital Environments / 디지털 환경**
3. **Experience Systems / 경험 시스템**

## LOCK CAP-02
**Technology Integration / 기술 통합**은 Cross-Capability로 한다.

## LOCK CAP-03
AI / Metaverse / Digital Twin / Theme Park는 Top-level Capability 이름으로 사용하지 않는다.

## LOCK CAP-04
과거 제품·기술은 각 Capability의 Evidence로 배치한다.

## LOCK CAP-05
Experience Systems는 현재 전략 방향을 보여주되 프로젝트 상태를 정확하게 명시한다.

## LOCK CAP-06
`Systems Integration` 대신 `Technology Integration`을 사용한다.

## LOCK CAP-07
Capability 전체는 Positioning인  
**Technology for Interactive Environments**  
를 증명해야 한다.

## LOCK CAP-08
Capability 페이지는 3개의 Core가 진화·확장되는 흐름과 1개의 Integration Layer가 결합된 구조로 설계한다.
