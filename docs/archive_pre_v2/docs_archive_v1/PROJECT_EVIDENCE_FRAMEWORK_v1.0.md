# 0. PURPOSE
# 0. 문서 목적

이 문서는 리본소프트 홈페이지에서 **어떤 프로젝트를 대표 사례로 보여줄 것인지**, 그리고 **각 프로젝트가 무엇을 실제로 증명할 수 있는지**를 통제한다.

This document governs **which projects should represent Rebornsoft on the website** and **what each project is actually allowed to prove**.

목표는 프로젝트 수를 많아 보이게 만드는 것이 아니다.

The objective is not to make the company look as if it has a large number of projects.

목표는 다음 세 가지다.

1. 현재 Positioning인 **Technology + Experience**를 실제 Evidence로 증명한다.
2. `Intelligent Interaction → Digital Environments → Experience Systems`의 회사 진화를 보여준다.
3. `Installed / Released / Contracted / Planned`의 차이를 숨기지 않으면서도 회사가 전문적으로 보이게 한다.

---

# 1. PROJECT ≠ PROOF
# 1. 프로젝트와 증거는 동일하지 않다

프로젝트 이름이 존재한다고 해서 동일한 수준의 실적이 되는 것은 아니다.

A project name does not automatically constitute the same level of proof.

예를 들어:

- 실제 설치 완료
- 정식 서비스 출시
- 공급계약 체결
- 공동개발 계약
- MOU
- 기획
- 제안

은 모두 다른 의미를 가진다.

따라서 모든 Project는 반드시 다음 두 값을 함께 가진다.

### PROJECT STATUS / 프로젝트 상태
무엇이 실제로 이루어졌는가?

### EVIDENCE GRADE / 증거 등급
그 사실을 현재 자료로 얼마나 강하게 증명할 수 있는가?

# 3. EVIDENCE GRADE SYSTEM
# 3. 증거 등급 체계

## GRADE A — PRIMARY VERIFIED
## 등급 A — 1차 직접 증빙

Examples / 예:
- Original contract / 원본 계약서
- Certification / 인증서
- Patent document / 특허 문서
- Inspection / completion document / 검수·완료 문서
- Actual project photography with identifiable context / 실제 구축 사진
- Released product or service material / 출시 서비스 원본 자료

### Website use
**Main project / main proof eligible**

---

## GRADE B — OFFICIAL COMPANY ARCHIVE
## 등급 B — 회사 공식 아카이브

Examples:
- Official IR
- Company profile
- Archived presentation
- Internal official project images

### Website use
**Usable**, but critical claims should preferably be upgraded with Grade A evidence.

---

## GRADE C — USER-APPROVED CURRENT FACT
## 등급 C — 사용자 최신 확정 사실

사용자가 현재 프로젝트에서 직접 제공·확정한 사실이나 상태.

### Website use
Can be used as a factual planning baseline, but externally sensitive claims should be supported by documents or visuals where possible.

---

## GRADE D — PROPOSAL / CONCEPT EVIDENCE
## 등급 D — 제안·컨셉 증거

Examples:
- Proposal
- Concept visualization
- Planned project deck

### Website use
Only as **Planned / Proposed / Concept**.

Never present as completed work.

# 5. PROJECT SELECTION CRITERIA
# 5. 대표 프로젝트 선정 기준

대표 프로젝트는 유명한 고객명이나 계약 금액만으로 선정하지 않는다.

Each selected project should score well across the following criteria.

| Criterion | KR | Weight |
|---|---|---:|
| Positioning Fit | Technology + Experience를 증명하는가 | 25% |
| Evidence Strength | 현재 자료로 방어 가능한가 | 20% |
| Visual Potential | 좋은 이미지·UI·영상으로 보여줄 수 있는가 | 20% |
| Evolution Value | 회사 발전과정을 보여주는가 | 15% |
| Current Relevance | 현재 방향과 연결되는가 | 10% |
| Global Readability | 해외 파트너가 이해하기 쉬운가 | 10% |

### Important
시각 자료가 약한 프로젝트는 사실이 강하더라도 Homepage Hero-scale case study로 사용하지 않을 수 있다.

A factually strong project does not automatically deserve a large homepage feature if its visual evidence is weak.

# 15. CLIENT / PARTNER NAME POLICY
